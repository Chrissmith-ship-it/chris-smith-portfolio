Worked example: where the margin actually went
A cut-down version of the realisation bridge I built at APCO. Takes contracted fees against time actually delivered and splits the gap into the parts you can do something about. The full version handles multi-currency and part-month joiners, which is most of the code and none of the interest.

import pandas as pd

# Rate card is by grade, not by person. Finance kept trying to use actual
# salary here, which just moves the problem somewhere less visible.
RATES = pd.read_csv("rate_card.csv")        # grade, standard_rate
TIME  = pd.read_csv("timesheets.csv")       # client, grade, hours
FEES  = pd.read_csv("contracted_fees.csv")  # client, fee


def realisation(time, rates, fees):
    t = time.merge(rates, on="grade", how="left")

    if t["standard_rate"].isna().any():
        missing = sorted(t.loc[t["standard_rate"].isna(), "grade"].unique())
        raise ValueError(f"no rate for grade(s): {missing}")

    t["value_at_rate"] = t["hours"] * t["standard_rate"]

    by_client = (
        t.groupby("client", as_index=False)
         .agg(hours=("hours", "sum"), value_at_rate=("value_at_rate", "sum"))
         .merge(fees, on="client", how="outer")
    )

    # Fee less what the work was worth at standard rates. Negative means we
    # delivered more than we sold, which is the number people argue about.
    by_client["gap"] = by_client["fee"] - by_client["value_at_rate"]
    by_client["realisation"] = by_client["fee"] / by_client["value_at_rate"]
    by_client["eff_rate"] = by_client["fee"] / by_client["hours"]

    return by_client.sort_values("gap")


bridge = realisation(TIME, RATES, FEES)

# Under 0.90 is worth a conversation. Under 0.75 and someone has been
# absorbing scope for months without telling anyone.
leaking = bridge[bridge["realisation"] < 0.90]
print(leaking.head(25).to_string(index=False))

Agentic AI

Built into a live close, not a proof of concept
Why agents rather than a scheduled script

Source data landed at different times from different markets, so a fixed schedule either ran too early on incomplete data or too late to be useful. People compensated by refreshing manually, which meant several versions of the same pack in circulation and review meetings spent reconciling to each other rather than to the business.

A scheduled job runs whether the data is ready or not. An agent waits for a condition, checks it holds, and only then acts. That is the difference that made it work. Time saved was useful; removing the version-control risk mattered more.

The controls around it
ScopeAgents read source systems and trigger refreshes. They do not post journals, change mappings or touch the ledger.
PreconditionsNothing runs downstream until the completeness checks pass. A failed check stops the chain and raises. It does not carry on with a warning.
Human checkpointMaterial movements and anything outside tolerance stop for review. The agent proposes, a person accepts.
ExplainabilityEvery run records what it saw, what it decided and why. Reconstructing a number means reading a log, not asking someone what they remember.
IdempotenceRe-running a step gives the same result. That sounds obvious until you have watched a half-finished refresh get run twice.
Failure modeFail loud and stop. In a close, quietly producing a plausible wrong number is far more expensive than producing nothing.

Where it goes next

From close orchestration to commercial insight

The close was the right place to start because the work is high volume and low judgement. The interesting application is commercial: variance detection across acquisition channels, contribution forecasting that updates itself, and first-draft commentary an analyst edits rather than writes. Same pattern, better return.

Driver-based variance attribution

Structured explanation instead of freehand commentary

Variance reported by driver, so volume, rate, mix, FX and timing, meaning a reviewer sees what moved and why rather than a number followed by a paragraph. Used at APCO to surface margin leakage across 100+ clients, and at WPP as the basis of the ExCo reporting rebuild adopted group-wide.

What I would not automate

Where the line sits

Judgement calls, anything that needs a conversation with the business, and any control that exists because someone has to be accountable for it. Automating those does not remove the risk, it removes the person who would have caught it. The value is giving the team back the hours they spent on data preparation, not taking people out of the loop.
Worked example: the orchestrator
Simplified, with the client-specific parts stripped out. The shape is what matters. Check before you act, retry what fails transiently, stop hard on anything that should not have happened, and write down what you did.

"""Month-end close orchestration.

Runs unattended from WD-1. Anything it cannot resolve it escalates
rather than guesses. See the note in check_ready().
"""
import logging
import time
from datetime import datetime

log = logging.getLogger("close")

MARKETS = ["UK", "FR", "DE", "IT", "ES", "BE", "NL"]
POLL_SECONDS = 600
MAX_WAIT_HOURS = 14        # if it has not landed by then, someone is on leave


def check_ready(market, period):
    """True once the market's ledger extract is complete for the period.

    Row count alone is not enough. A part-loaded extract looks healthy.
    Checking the control total against the ledger caught two silent
    partial loads in the first quarter, which is why this exists.
    """
    extract = source.fetch_extract(market, period)
    if extract is None:
        return False

    if not extract.control_total_matches():
        log.error("%s %s: control total mismatch, stopping", market, period)
        raise DataIntegrityError(market, period)

    return extract.is_complete()


def wait_for(market, period):
    deadline = time.time() + MAX_WAIT_HOURS * 3600
    while time.time() < deadline:
        if check_ready(market, period):
            log.info("%s ready", market)
            return True
        time.sleep(POLL_SECONDS)

    notify.escalate(f"{market} {period} did not land within {MAX_WAIT_HOURS}h")
    return False


def refresh_plan(period, attempts=3):
    # Adaptive returns 5xx if you hit it during their nightly window.
    # Backing off is cheaper than moving our whole schedule around it.
    for n in range(attempts):
        try:
            return adaptive.refresh(period)
        except TransientError as e:
            wait = 2 ** n * 30
            log.warning("refresh failed (%s), retrying in %ss", e, wait)
            time.sleep(wait)
    raise RuntimeError(f"refresh failed after {attempts} attempts")


def run(period):
    started = datetime.utcnow()
    ready = [m for m in MARKETS if wait_for(m, period)]

    if len(ready) < len(MARKETS):
        missing = sorted(set(MARKETS) - set(ready))
        # Deliberately not proceeding on a partial set. A pack that is
        # right for five markets and quietly missing two is worse than
        # no pack at all.
        notify.escalate(f"{period}: missing {missing}, close paused")
        return

    version = refresh_plan(period)
    packs = reporting.build_all(period, version=version)

    flagged = variance.material_movements(period, version=version)
    if flagged:
        notify.for_review(flagged, packs)     # human accepts before publish
        log.info("%d movements held for review", len(flagged))
    else:
        reporting.publish(packs)

    audit.write(
        period=period,
        version=version,
        markets=ready,
        packs=[p.id for p in packs],
        held=len(flagged),
        started=started,
        finished=datetime.utcnow(),
    )

Worked example: variance attribution helper
Stripped-down version of the kind of script I keep around for month-end. Reads actuals and budget, joins on cost centre and account, flags material variances and ranks the top drivers.
Show the snippet 
import pandas as pd

MATERIALITY = 50_000

actuals = pd.read_csv("actuals.csv")
budget  = pd.read_csv("budget.csv")

df = actuals.merge(
    budget,
    on=["cost_centre", "account"],
    suffixes=("_act", "_bud"),
    how="outer",
).fillna(0)

df["variance"]    = df["amount_act"] - df["amount_bud"]
df["variance_pc"] = df["variance"] / df["amount_bud"].replace(0, pd.NA)
df["material"]    = df["variance"].abs() >= MATERIALITY

top = (
    df[df["material"]]
      .sort_values("variance", key=abs, ascending=False)
      .head(15)
)

print(top[["cost_centre", "account", "amount_bud", "amount_act", "variance", "variance_pc"]])
